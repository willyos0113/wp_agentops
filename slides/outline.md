# 簡報大綱

---

## 一、業務情境與達成目標

- 公司主要業務販賣貓咪食品用品店，初期預估人數OOO，採 WordPress 為公司規劃一個OO平台。
  - 用戶規模估算: OOO。
  - 核心目標: 確保平台資料庫安全，自動化維運減少人力負擔。

- 以 Web/DB 分離加上 CloudWatch 自動調查，達成資料庫不對外、系統故障自動產出根因報告。

## 二、想解決的問題

- 資料庫安全性：平台涉及用戶隱私，資料庫安全性很重要。
- 維運人力不足：公司規模小人力不足，需減輕人力維運負擔。

## 三、如何解決問題?

- 資料庫安全性：採內外網段隔離，只有平台 AP 才可以連線內網資料庫，以提升資料庫安全性。
- 維運人力不足：平台 AP 日誌自動拋轉到監控平台，再利用監控平台 AI 自動調查日誌、操作紀錄等，提供根因分析報告給維運人員，減少人力排查的時間成本。
- 架構方案評估：
  - 資料庫維運成本比較
  - 自動監控人力成本比較

## 四、解決前後比較

- 解決前：
  - 資料庫：Web/DB 同一台，且均可對外連線
  - 故障發生時：等用戶回報
  - 故障排查：人工登機器翻 log、AWS web console 設定
- 解決後：
  - 資料庫：DB 獨立於內網，只有 Web 主機才能連線
  - 故障發生時：1~2分鐘內出現 5xx 告警信，10分鐘後自動產出分析報告
  - 故障排查：AI自動調查 Web 日誌、RDS 指標、CloudTrail 變更紀錄

- 故障演練時間軸(故障 -> 告警 -> 調查完成 -> 恢復)所需時間。

## 五、技術實踐

- 整體架構圖：VPC、public/private subnets、EC2、RDS，及監控流程
- 故障演練示範：移除 DB SG 的 3306 規則 → 網站 500 → 告警信 → 調查結果指出 SG 規則被移除 → terraform apply 還原。這是整份簡報最有畫面的一段，建議獨立一頁並放截圖。
- 權限設計：Agent 只讀不改、全部用 IAM role、沒有新增長期金鑰，剛好呼應「安全性」這個主題。
